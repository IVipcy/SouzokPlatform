# 金融調査：証券・信託タブの仕様（2026-09-09）

預金タブの型（工程図 → ①最初の連絡 → ②請求方法 → ③請求）を踏襲し、証券会社・株主名簿管理人（信託銀行等）・ほふりを1つのタブで扱う。

## なぜ1つのタブか

- どこの証券会社に株があるか面談では分からない案件は、まず **ほふり（証券保管振替機構）に開示請求** する。
- 開示結果には **証券会社の取引口座** と **信託銀行の特別口座（単元未満株など）** が一緒に載る。ほふりの結果を読んだ時点で、証券会社と株主名簿管理人の両方が調査先として決まる。
- 証券会社の残高証明から登録した **銘柄** には、それぞれ株主名簿管理人がいる。配当の未払いや特別口座があれば、その管理人にも請求する。
- 3つが1本の流れなので、タブを分けると行き来のたびに跨ぐことになる。

## 画面

### 左レール
```
一覧（TOP）
ほふり照会              ← 案件に1つの入口。押すと無ければ作る（kind=ほふり）
証券会社                ← 小見出し
  野村證券          3
株主名簿管理人（信託銀行等）
  三井住友信託銀行  2
＋ 調査先               ← 証券会社／株主名簿管理人だけ選べる（ほふりはレール先頭から）
```

### ほふり照会のページ
- ① ほふり照会：要否（不要＝保有先が判明している）／調査対象住所／開示請求日／結果到着（チェック＝今日）
- ② 判明した口座管理機関：1行1機関。機関名／区分（証券会社・株主名簿管理人）／口座の種類（取引口座・特別口座・その他）／「＋ 調査先に追加」。追加すると左レールに増え、行は「✓ 追加済み」になる。同名の調査先があれば紐づけるだけ。
- 次の対応：未請求→「ほふりへ開示請求」／請求後→「開示結果の到着待ち」／到着後、行が無い→「開示結果の機関を登録」、未追加あり→「判明した機関を調査先に追加」／全行追加→「照会完了」
- テーブル：`financial_jasdec_results`（migration 274）

### 証券会社・株主名簿管理人のページ
- 手続き：預金と同じ ProcedureCards。証券会社は ①死亡連絡・依頼書（全店調査なし）→②→③。株主名簿管理人は ①依頼書 →（②なし）→ 請求。
- 請求：請求モーダルは調査先の種別で書類名が変わる
  - 証券会社：残高証明（指定日／直近日）＋顧客勘定元帳（任意・期間）。対象口座の選択なし
  - 株主名簿管理人：所有株式数証明書（基準日）＋未受領配当金明細書（任意・期間）。対象口座の選択なし
- 銘柄（新設）：銘柄名／コード／種類／数量／単価／評価額／基準日／**株主名簿管理人**（証券会社のみ）／備考
  - 種類が国内株式・ETF・REIT のとき管理人を入れる。入力候補は主要信託銀行。東京証券代行・日本証券代行は三井住友信託銀行に名寄せ
  - 管理人を入れると「＋ 調査先」で信託銀行の調査先が生まれる（既にあれば ✓ で開く）
  - 投資信託・債券・外国証券・その他は管理人「対象外」
  - `admin_status`：未特定／特定済／対象外。次の対応「株主名簿管理人の特定」は未特定が残っている間

### TOP（一覧）
1行1銘柄。調査先・次の対応・進行中のタスクは調査先ごとに縦結合。列＝調査先／銘柄／種類／数量／評価額／株主名簿管理人（✓追加済み・未追加・未特定・対象外）／次の対応／進行中のタスク。ほふりは1行で「開示結果 n機関 → 調査先へ m／n」。

## データ

| 対象 | テーブル | 備考 |
|---|---|---|
| ほふり照会 | financial_institutions (kind=ほふり) | 案件に1つ。jasdec_* 列 |
| 開示結果の機関 | financial_jasdec_results | 274。institution_id が入れば追加済み |
| 証券会社／管理人 | financial_institutions (kind=証券／株主名簿管理人) | 既存 |
| 銘柄 | securities_holdings | institution_id で調査先に属する。administrator／admin_status |
| 請求 | financial_requests／items | 書類名だけ種別で違う |

オーダーシート側（調査前）は従来の「証券口座」「信託口座」の入力欄のまま。実務タブだけ「証券・信託」に統合。
