## 4. 裏付けとなる実装事実（ここに書いてあることは実在する）

資料に具体性を持たせるための材料。**この範囲内で書くこと。**

### 規模

- 業務用テーブル約 **70**、DBマイグレーション **255** 本（＝業務に合わせて作り込み続けている証拠）
- 稼働環境：Azure Container Apps（東京）／ Supabase（東京）

### AI が実際に動いている箇所（すべて Claude）

| 用途 | 内容 |
|---|---|
| 手書きメモの文字起こし | 面談中に紙・タブレットに書いた手書きメモの画像を、その場でテキスト化 |
| 手書き／テキストからの**項目自動反映** | 文字起こし結果から「氏名」「生年月日」「住所」等の**項目を構造化抽出**し、入力欄へ自動で流し込む。表形式（複数行）にも対応 |
| **進捗サマリーの自動生成** | 案件の工程別の作業内容メモ・タスク実施結果・状態をまとめて渡し、**全体1〜2文＋工程ごと1文**の要約を生成。管理担当が案件を開いたときにオンデマンドで1回だけ実行 |
| 請求書画像の読み取り | 提携先から届いた請求書の画像から、明細（種別／報酬額／税）と実費を構造化抽出し、自社の請求内訳へ反映 |
| 社内マニュアルの執筆補助 | 推敲・構造化・要約・加筆、題材からの下書き生成 |

### 書類の自動生成（テンプレート差し込み・全12種）

請求書／確定請求書／戸籍請求書／固定資産評価証明請求書／契約書／委任状／封筒／原本預り証／原本受領書／財産目録／事件簿／郵送確認書

- 案件データから Excel・Word テンプレートへ差し込んで生成し、そのまま案件に添付・保管される
- 相続業務の実務書式に合わせた作り込み（帳票の体裁・和暦・押印欄など）

### 請求・入金

- 案件ごとに**請求パターン**（段階請求／一括＋実費／一括のみ）を選べる
- 入金の**CSV突合を自動化**。突合結果を4段階（確定／要確認2種／CSVのみ）で判定し、要確認だけ人が見る
- 確定売上表レポート・経費レポートの出力（Excel）
- 経理⇄現場の**確認依頼・返金依頼ワークフロー**（依頼→回答→確定）

### タスク・進捗

- 受注区分 → 業務 → タスクの3層で、案件ごとに作業を展開
- **着手OK判定**・**完了ゲート**（前工程の受領確認や管理担当の確認が済むまで進めない）
- 前段作業の評価（〇／△／×）が担当者×作業で蓄積される
- 管理担当と事務担当で**見える一覧が役割ごとに分かれる**

### 案件の見える化

- 案件の**色＝アラートの最大深刻度**で統一（期限超過・要確認などが一目で分かる）
- アラートセンター（やること＋履歴）をマイページに集約
- ダッシュボード：事業部／事務所／チーム／個人／ランキング／今日やること

### 書類の電子化・紙の最小化

- 受領書類の**受信簿**で「何を受け取ったか／まだか」を管理
- 案件ごとに1フォルダで添付ファイルを保管し、アップロード時に受信簿と突合
- 戸籍などの画像も案件に紐づけて保管

### 現場の入力導線

- **面談シート**（スマホ／タブレットで面談中に入力。手書きメモ→AI反映もここ）
- **オーダーシート**（受注後に内容を肉付けする独立アプリ）
- 面談シート → オーダーシート → 実務タブが**同じデータを共有**し、二重入力がない

### 外部連携

- 提携LPからの案件情報を受信（HMAC署名付き）。受信箱に入り、面談登録した時点で案件番号を採番

### その他

- アプリ内マニュアル（検索付きナレッジベース）
- 報連相（情報共有／要対応の2種別。要対応は期限管理付き）

## 5. 社労士業務への読み替え（資料の肝）

相続の用語のままでは伝わらない。**「うちの仕事だとこうなる」が想像できる形に翻訳すること。**
以下は読み替えの方向性。かがやきの業務メニュー（§2）に寄せて具体化する。

| オーシャンでの実装 | 社労士事務所での読み替え例 |
|---|---|
| 案件（相続手続き1件） | 顧問先ごとの手続き案件（入退社手続き、算定基礎、労働保険年度更新、就業規則改定、助成金申請 など） |
| 面談シート（面談中にスマホ入力・手書きAI反映） | 顧問先訪問・労務相談のヒアリングシート。その場で書いたメモをAIが項目化 |
| 受注区分→業務→タスクの3層展開 | 手続き種別を選ぶと、必要な作業・提出物・期限が自動で並ぶ |
| 着手OK・完了ゲート | 顧問先からの必要書類が揃うまで次工程に進ませない |
| 進捗サマリーAI | 顧問先ごとの「今どこまで進んでいるか」を1〜2文で自動要約 |
| 書類の自動生成（12種） | 36協定・雇用契約書・就業規則の変更届・各種届出書・委任状 などの雛形差し込み |
| 受信簿＋案件1フォルダ | 顧問先から預かった書類の受領管理と電子保管 |
| 請求パターン＋入金CSV突合 | 顧問料（月額）＋スポット報酬の請求と入金消込 |
| アラート色統一 | 法定期限（5日以内・翌月10日など）の遅延を色で即座に把握 |

> 上表は**読み替えの提案**であり、社労士業務での実装実績ではない。
> 資料上も「相続業務での実装 → 社労士業務ではこう応用できる」と、
> **実績と提案の線引きが分かる書き方**にすること。

## 6. 数値の扱い（重要・厳守）

「従来100人体制のうち約10%の稼働削減」は、**現時点では試算・目標値**として扱うこと。

- **「削減しました」と実績のように断定して書かない。**
- 「〜を見込む」「試算」「目標」と明示する。
- 単に「10%削減」と置くのではなく、**どの作業が減るのかを分解して示す**。例：
  - 面談メモの清書・転記（手書き→AI項目反映で消える）
  - 同じ情報の二重入力（面談シート／オーダーシート／実務でデータ共有）
  - 書類作成の手打ち（12種の自動生成）
  - 入金消込の目視突合（CSV突合で「要確認」だけ人が見る）
  - 進捗確認のための問い合わせ・報告（進捗サマリー自動生成）
  - 紙書類の探索・保管（電子化＋受信簿）
- 実測値があるなら、その出所を併記する。**なければ「試算」と明記する。**

## 7. 構成案（1枚のレイアウト）

1. **見出し**：AIネイティブな業務管理システム（一言で何か）
2. **リード文 2〜3行**：汎用SaaSに業務を合わせるのではなく、**業務にシステムを合わせた**。その上でAIを日々の動線に組み込んだ
3. **柱4つ**（アイコン＋見出し＋2行）
   - 顧客・案件情報を1か所に
   - タスクと進捗を自動で見える化（AI要約）
   - 書類作成・請求をAIと自動生成で
   - 紙をなくし、案件に紐づけて保管
4. **AIが効いている場面**：手書きメモ→項目反映／進捗要約／請求書読み取り の3点を、before→after で
5. **なぜ汎用SaaSではないのか**：業務に合わせた作り込み（テーブル70・改修255回・役割ごとの画面分離・着手/完了ゲート）
6. **効果（試算）**：§6 の分解を短く
7. **社労士事務所ではこう使える**：§5 の読み替えを3〜4行
8. **フッター**：オーシャン内製／技術構成を1行（Azure東京・Claude）

## 8. トーン・デザイン

- 落ち着いた業務システムの見た目。**青＝構造／緑＝完了／琥珀＝進行中／赤＝危険**の役割を守る
- 角は控えめ、フラット。装飾より情報の並びで読ませる
- 専門用語（マイグレーション、テーブル、HMAC 等）は**表に出さない**か、平易に言い換える
  - 例：「マイグレーション255本」→「業務の変化に合わせて255回作り替えてきた」
- 誇張表現・煽り文句を使わない。事実の積み上げで説得する
- スクリーンショットは**この資料には貼らない**（実データが写るため）。必要なら模式図で示す

## 9. やってはいけないこと

- §4 にない機能を「できる」と書く
- 稼働削減率を実績として断定する（§6）
- 顧客名・実案件・実データを載せる
- かがやき側の顧客数・規模を推測して書く
- 社労士業務での導入実績があるかのように書く
