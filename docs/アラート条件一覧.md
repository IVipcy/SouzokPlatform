# 通知・アラート 全一覧

システムが自動で出す「気づかせるもの」の全条件。2026-08-08 時点の実装に一致。

**営業日の定義**：日曜と祝日を除く日。**土曜は営業日**。祝日は法律どおり計算（`src/lib/holidays.ts`）。

## 4つの系統

同じ事象でも系統によって出る／出ないが分かれる。役割が違うため。

| 系統 | 役割 | どこに出る | 実装 | 数 |
|---|---|---|---|---|
| ① バナー | **放置の検知**（日数が経ったもの） | マイページ上部 → 要対応（期日超過）一覧 | `overdue.ts` / `caseStateAlerts.ts` | 12 |
| ② 案件チップ | **その案件の健康状態**（案件色を決める） | 案件詳細ヘッダー・案件一覧の色 | `alerts.ts` | 11 |
| ③ アラートセンター | **今日やること**（自分向けのTODO） | マイページのベル | `/api/alerts` | 16 |
| ④ 通知 | **イベントの連絡**（誰かの操作で1回だけ飛ぶ） | ベルの履歴 | `notifications` テーブル | 19 |

①②③は毎回その場で計算する（消すには原因を解消する）。④だけはレコードとして残り、既読で消える。

# ① バナー（要確認／要注意）

マイページ上部の2つのバナー。クリックで要対応一覧へ。

## 1-A 入金期日超過（請求）

対象：`invoices` のうち ステータス＝入金待ち。起点＝入金期日。

| 条件 | 重要度 |
|---|---|
| 入金期日を **5営業日** 超過 | 要確認（黄） |
| 入金期日から **14日**（暦日）経過 | 要注意（赤） |

## 1-B タスク期日超過

対象：未完了タスク（完了・キャンセルを除く）。起点＝タスクの期日。

| 条件 | 重要度 |
|---|---|
| 期日を **5営業日** 超過 | 要確認（黄） |
| 期日から **14日**（暦日）経過 | 要注意（赤） |
| 優先度が **超急ぎ** の未完了タスク | 要注意（赤）※期日前でも出る |
| 期日超過が 1〜4営業日 | 軽微（バナーには出ない） |

## 1-C 案件アラート

| アラート | 対象ステータス | 条件 | 起点 | 重要度 | 対象者 |
|---|---|---|---|---|---|
| 管理担当 未アサイン | 受注／戻り受注／作業着手準備 | 管理担当が未設定のまま **2営業日** | 受注日 | 要注意 | 受注担当 |
| オーダーシート未完成 | 同上 | 未完成のまま **3営業日** | 受注日 | 要確認 | 受注担当 |
| オーダーシート未完成 | 同上 | 未完成のまま **5営業日** | 受注日 | 要注意 | 受注担当 |
| 前受金 未請求 | 同上 | 前受金の請求書が無いまま **5営業日** | 受注日 | 要注意 | 受注担当 |
| 到着物あり（未開封） | 問わない | 郵送物一式が到着連絡済で未開封 | 到着連絡日 | 要確認 | 受注/管理担当 |
| 案件報告：至急 | 問わない | 状態＝「至急！！」の報告が未確認 | 報告日 | 要注意 | チーム全員 |
| 案件報告 未回答 | 問わない | 至急以外の報告が未確認のまま **3営業日** | 報告日 | 要確認 | チーム全員 |

「管理担当を割り振らない」にした案件では 管理担当 未アサイン は出ない。

# ② 案件詳細のチップ（案件色）

案件色は最大深刻度で決まる。**紫 ＞ 赤 ＞ 黄 ＞ 青**。閲覧者のロールに関係なく同じものが出る。

| チップ | 条件 | 深刻度 |
|---|---|---|
| クレーム | クレームありフラグ かつ 進行中 | 紫 |
| タスク期限超過 | 期限超過の未完了タスクが1件以上 | 赤 |
| 管理担当 未アサイン | 受注〜作業着手準備 かつ 未設定 かつ 受注から2営業日超過 | 赤 |
| 前受金 未請求 | 受注〜作業着手準備 かつ 請求書未発行 かつ 受注から5営業日超過 | 赤 |
| 前受金 未入金 | 前受金請求書が 作成済 または 入金待ち | 赤 |
| 完了予定日 超過 | 完了予定日を過ぎている（完了・失注を除く） | 赤 |
| 未対応 10営業日超 | 最後に案件を開いてから10営業日超過 | 赤 |
| 週次報告の漏れ | 直近7日に確認済の進捗報告がない | 黄 |
| 面談メモ未記載 | 面談日を過ぎたのに面談実施日が未入力 | 黄 |
| 回答予定日 間近／超過 | お客様回答予定日が2日以内 or 超過 かつ 確認タスク未完了 | 黄 |
| 未対応 5営業日超 | 最後に案件を開いてから5営業日超過 | 黄 |

「進行中」＝ 受注／戻り受注／作業着手準備／対応中。

# ④ 通知（イベント連絡）

誰かの操作をきっかけに1回だけ飛ぶ。既読にすると消える。日数条件は無い。

| 種別 | 誰に | いつ飛ぶ |
|---|---|---|
| 管理担当の割振り依頼 | 割振り担当 | 割振り依頼ポップで「依頼する」 |
| 相談案件が引き継がれました | 引き継ぎ先 | 引き継ぎモーダルで確定 |
| タスクが割り当てられました | タスク担当者 | タスクの担当者に指定された |
| 【超急ぎ】前受金入金御礼連絡 | 受注担当 | 前受金の入金が確定した（タスクも自動生成） |
| 到着物あり | 受注/管理担当 | 郵送物一式の到着を登録した |
| 追加戸籍請求の承認依頼 | 管理担当 | 事務が戸籍請求を追加した |
| 不動産（市区町村）追加の承認依頼 | 管理担当 | 事務が市区町村を追加した |
| 案件報告が届きました | 受注担当 | 管理担当が案件報告を出した |
| 案件報告が確認されました | 管理担当 | 受注担当が案件報告を確認した |
| 業務完了申請が届きました | 受注担当 | 管理担当が業務完了を申請した |
| 進捗確認が確認されました | 管理担当 | 受注担当が進捗確認に回答した |
| 管理担当の確認依頼 | 管理担当 | 残高確定・評価額確定などの確認依頼 |
| クレーム報告 | 受注担当・上長 | クレームを登録した |
| クレーム報告が確認されました | 報告者 | クレームが確認された |
| 経理から連絡があります | 受注/管理担当 | 経理メモが更新された |
| 入金確定 | 受注担当 | 入金の突合が確定した |
| 入金が確定しました | 依頼者 | 入金確認依頼に回答があった |
| 確認依頼に回答がありました | 依頼者 | 経理が確認依頼に回答した |
| 返金の最終承認をお願いします／返金を確定しました／返金が却下されました | 経理・依頼者 | 返金フローの各段階 |

# 定義の置き場所

判定は **`src/lib/alertRules.ts` の1ファイルだけ**にある。しきい値は `ALERT_DAYS` / `ALERT_CAL_DAYS`。
バナー・案件チップ・ベルは、この関数が返した結果を並べ替えて表示しているだけなので、
条件を変えるときは alertRules.ts だけを直せばよい。

| 画面 | 何をしているか |
|---|---|
| バナー（`caseStateAlerts.ts`） | 結果のうち claim/high→要注意、mid→要確認 に振り分ける。info は出さない |
| 案件チップ（`alerts.ts`） | 結果をそのまま並べる。案件色＝最大深刻度 |
| ベル（`/api/alerts`） | 結果を「自分向け（audience）」で絞って並べる。info も出す |

案件色は **一番重いアラートの色**でしかない。紫＞赤＞黄＞青。
アラートが1つも無ければ青（順調）。
